The plan's Phase 0, the first slice of Phase 1, and Phase 4b landed before this session. Remaining:

- [ ] **Phase 1 rest — the per-tile-set OSM query (TODO #6).** `roads()` is still one Overpass query
      for the whole region. Add an offline path: take a Geofabrik extract and clip it to each
      tile-set (`osmium extract -p`), so a tile-set's plan never holds the world. The bake's `plan`
      step queries per tile-set. Keep the global `spine_utm.json` as a rollup until Phase 3.
      **Held, with the reason (2026-10-12):** not done this pass — see the note below on why it
      cannot land safely before Phase 3.
- **Why Phase 1-rest was not rushed.** `netsets.cut_line` records each piece's `s0`/`s1` as metres
  along the ORIGINAL chain, and `assign` computes neighbours' context from the same global chain
  set. A per-tile-set query has no single original: each tile-set would clip the chain to its own
  halo (e.g. 4 km + 300 m), so the same seam-spanning road arrives in two tile-sets as two chains
  with different starts and different total lengths. Feeding those through `assign` double-counts
  the owned piece (one halo's remaining piece overlaps the neighbour's owned piece) and gives the
  two sides different `s` for the same seam node. `s` only becomes well defined per segment once
  Phase 3 drops the world primary for per-segment profiles; that is when the local chains can be
  cut exactly once and the seam node can be shared without a global chain to project onto. Landing
  the sourcing first would be a subtly-wrong seam — worse than the long poly it removes.
- [ ] **Phase 2 — the per-tile-set junction model.** `intersections.py` runs whole-network. Move it
      per tile-set, with the halo supplying seam approaches. Large; may land as a working slice.
- [ ] **Phase 3 — per-tile-set profiles/pyramid.** Deferred if 1–2 consume the pass.
- [ ] **Phase 4 — finalize as a union of independent tilesets.** The finalizer stitches one primary;
      it should union per-tile-set artifacts instead.
